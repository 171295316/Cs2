# P4 页面、质量与上线准备

## 实现

- 中文深色响应式首页、分类、目录搜索、详情（变体、价格、供给）、来源方法说明。
- 近期有效样本排行：固定来源/币种/口径/原始每日粒度；默认 7 天，只用每件基础物品最新记录，不混不同变体或过期样本。不做单值估算总量排行。
- 复合时间序列索引（迁移 0005）；首页不加载图表库，图表仅出现在详情页。
- 来源方法页元数据使用 15 秒服务端缓存；价格、供给、目录和授权判断实时查询，不缓存撤销后的读数。
- HTTP 请求体 2 MiB、每批最多 1000 行；进程内每 IP 600 请求/分钟、健康检查豁免、有界 IP 状态；多副本全局限流应由部署入口提供。
- 请求 ID、状态码和路径的结构化日志，不记录 Bearer token、请求体或查询参数。API/Web 基础安全响应头；精确金额和数量作为字符串返回，避免 JavaScript 丢失整数精度。
- 来源撤销后目录/详情被隐藏；专项价格/供给授权撤销后读数立即不可见。审批接口不暴露 HTTP。
- 生产 Docker 镜像排除 tests，不安装 pytest/httpx；浏览器合成种子只允许显式命名的隔离 cs2_e2e 数据库且需要 CS2_E2E_MODE=1。

- 导入事务记录 job_id、成功/失败状态与时间，失败审计不保存正文或凭证；失败批次数据仍整体回滚。

## 验证

本地：62 项后端测试通过；1 个 PostgreSQL 专项因本地无服务跳过。3 项真实 Chromium 浏览器测试通过（空态、价格/供给/缺口/变体/文本转义、手机首页和排行）。Ruff/mypy、ESLint/TypeScript、Next.js 生产构建通过。后续微调与最终提交的完整结果以 PR 中 CI 记录为准。

SQLite 升级到 0005，迁移升级/回滚由本地与 PostgreSQL CI 验证。CI 在独立数据库 cs2_e2e 中显式安装演示记录，Compose 检查则保持空生产配置。没有声明这些合成记录是真实价格或存世量。

## 上线边界

工程支持一键 Compose 启动，不代表已购买供应商、获得二次分发权或正式上线。需要域名/TLS、管理网络隔离、数据库备份和资源预算；服务端外部数据供应商仍禁用。未提供自动交易或个人 Steam 库存功能。估算只接收有明确依据与区间的记录，不自动训练或生成总量。
